HTML is the language of web pages, but it is also a convenient way to write documents: an invoice template, a report generated by a script, a newsletter saved from an email, a page of notes exported from a wiki. When such a document has to be sent, printed or archived, a PDF is the format everybody can open.

This guide explains how to convert HTML to PDF in your browser, which parts of HTML are supported, why the tool does not take web page addresses and how to prepare your HTML for a clean, readable result.

:::takeaways
- Choose an HTML file or paste your HTML, pick a page size and convert. The PDF has real, selectable text.
- Headings, paragraphs, lists, tables, links, bold and italic text and embedded pictures are converted.
- CSS styles, scripts, web fonts, columns and positioned elements are not applied.
- You cannot enter a web address. Save the page as an HTML file first and use that file, or paste its HTML.
- The HTML is read as inert text: scripts do not run and nothing is loaded from the internet.
:::

## What the converter reads

The tool reads the structure of your document and lays it out as a simple, clean PDF. It understands:

- Headings and paragraphs.
- Ordered and unordered lists.
- Tables.
- Links, bold and italic text.
- Pictures that are embedded in the HTML itself, using data addresses.

It does not try to reproduce a web design. A page that depends on CSS for its look, with columns, floating boxes and custom fonts, will come out as a plain document: the content in reading order, without the styling. This is a deliberate trade-off. It keeps the conversion predictable and safe.

## Why you cannot enter a web address

It is natural to expect a box for a web address. The tool does not offer one, for two reasons. First, fetching other websites would mean sending the address to a server, which would break the promise that your work stays on your device. Second, a page rarely converts well without its styles and scripts, and the fetched result would disappoint.

The workaround is easy: in your browser, save the page as an HTML file, or view its source and copy it, and then use that file or paste the code. For pages with a lot of styling, expect a plainer result.

## What is not converted

- Scripts, which do not run.
- Forms, frames, canvas elements, video and SVG graphics.
- Pictures and style sheets loaded from other websites. They are skipped, not fetched.
- CSS layout: columns, positioning, backgrounds and web fonts.

The tool lists what it left out, so you know whether the PDF is complete enough.

## Is it safe to convert HTML you do not trust?

The HTML is read as inert text. Scripts are not executed and nothing is loaded from the internet, so a hostile page cannot run code or ping a tracking address through the conversion. Only pictures embedded in the HTML are used. That makes the tool a reasonable way to turn a saved email or a downloaded page into a document without opening it in a browser tab.

## Preparing HTML for a good PDF

A few habits make the output better:

1. Use real headings, not bold text, for titles. Headings give the document a structure.
2. Use proper lists and tables instead of spaces and dashes.
3. Embed important pictures as data addresses, or they will be skipped.
4. Keep the document in a single column.
5. Add a clear title and short paragraphs. Long unbroken blocks are hard to read on paper.
6. Save the file with UTF-8 encoding so that special characters come through.

## Languages and fonts

The PDF is written with Noto Sans, which covers Latin letters, including Polish, Czech, Romanian and Turkish characters, as well as Cyrillic, Greek, Vietnamese and Devanagari. Arabic, Hebrew, Thai, Chinese, Japanese and Korean text is not supported yet. Those characters appear as question marks, and the tool tells you how many were affected. The original fonts of the document are not kept.

## Common mistakes to avoid

- Expecting the PDF to look like the web page in a browser.
- Referencing pictures by web address, which are skipped.
- Pasting only a fragment without the surrounding structure and wondering about the layout.
- Not checking special characters in languages the font does not cover.
- Not keeping the HTML source. The PDF cannot be turned back into the original page.

## A quick checklist

1. Save the page as an HTML file, or copy its HTML.
2. Make sure pictures are embedded and the text is real text.
3. Choose a page size and convert.
4. Read the notes about skipped items and check the PDF.
5. Keep the HTML source.
